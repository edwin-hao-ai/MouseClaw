## 1. Autostart（开机自启动）

### 决策

- 用 `tauri-plugin-autostart` 插件，macOS 上自动选 `LaunchAgent` 机制
  （插件帮我们抹平 macOS 13+ 的 `SMAppService` vs ≤12 的传统 plist）
- 启动时传 `--minimized` 参数 → `main.rs` 检测，仅隐藏所有窗口、不弹
  Onboarding、注册快捷键照常
- 默认值：Onboarding 第 5 步「权限」里**默认勾选**，但需用户主动确认
- 用户随时可在 3 个入口控制：
  1. Onboarding 第 5 步勾选框
  2. 托盘菜单 `☑ 开机自启动`（带勾选状态）
  3. 「关于 MouseClaw」面板里再放一份兜底

### Config 新字段

```rust
// config.rs
pub struct Config {
    ...
    /// v0.1.26 · 开机时自动启动 MouseClaw
    #[serde(default = "default_autostart")]
    pub autostart: bool,
}
fn default_autostart() -> bool { true }  // schema 升级时已用户老配置默认开
```

### 实现要点

```rust
// lib.rs · run()
.plugin(tauri_plugin_autostart::init(
    tauri_plugin_autostart::MacosLauncher::LaunchAgent,
    Some(vec!["--minimized"]),
))

// setup hook 里同步状态：
let autostart = app.autolaunch();
let cfg_says = Config::load().autostart;
let system_says = autostart.is_enabled().unwrap_or(false);
if cfg_says != system_says {
    if cfg_says { autostart.enable()?; } else { autostart.disable()?; }
}
```

**反向同步：** 进程启动时若发现系统状态 ≠ config（用户在 系统设置 →
登录项 里手动关掉），以系统状态为准回写 config。

### Tray 菜单条目

```rust
// tray.rs
MenuItem::with_id(
    app, "toggle-autostart",
    if cfg.autostart { "✓ 开机自启动" } else { "开机自启动" },
    true, None,
)
```

点击 → 翻转 config + 调用 `enable()/disable()` + 重建菜单。

### Onboarding 第 5 步增加 toggle

```tsx
<label className="ob-perm-row">
  <input type="checkbox" checked={autostart} onChange={...} />
  <div>
    <div className="ob-perm-title">{t("onboarding.autostart.title")}</div>
    <div className="ob-perm-sub">{t("onboarding.autostart.sub")}</div>
  </div>
</label>
```

i18n keys:
- `onboarding.autostart.title`：「开机自启动」/ "Launch at login"
- `onboarding.autostart.sub`：「登录 Mac 时自动启动 · 住在菜单栏」/
  "Starts when you log in · lives in your menu bar"

## 2. Pet Picker Window（重做选择器）

### 现状 vs 痛点

- ✅ Onboarding 第 3 步已经有 3×2 网格 + PixelMouse 预览，那部分**OK**
- ❌ 托盘菜单只能展示 `🐭 经典灰 · 🤍 小白鼠…` 这种 emoji + 文字 ——
  macOS native menu 不支持内联图片渲染
- ❌ 用户在 Onboarding 之后想换，只能盲选托盘菜单里的 emoji

### 决策

新增一个 Tauri 子窗口 `picker.html`，作为**桌宠选择 + 管理面板**。
托盘菜单的「更换桌宠」子菜单**整组删掉**，替换为单条
`🎨 更换桌宠…` 点击打开此窗口。

### 窗口规格

```jsonc
// tauri.conf.json windows[]
{
  "label": "picker",
  "title": "选择你的桌宠",
  "url": "picker.html",   // 或 /picker SPA 路由
  "width": 720, "height": 560,
  "resizable": false, "minimizable": true, "maximizable": false,
  "visible": false,        // 默认不显示，由 commands::open_picker() 唤起
  "skipTaskbar": false,
  "decorations": true,
  "alwaysOnTop": false
}
```

### 交互

- 单击卡片 → 临时切换（窗口大预览 + 菜单栏老鼠都立即换）
- 双击卡片 OR 点击「应用并关闭」 → 写 config，关窗
- 关窗时若未应用 → 提示「保留当前预览？」 OR 自动还原（看用户测试）
- 卡片 hover → 触发 idle 动画（PixelMouse state="listen" → "jump"
  循环 800ms 一次）—— 默认状态太静，hover 给反馈

### 路由 / 状态

- 复用现有 `src/skins.ts` SKINS 数组（v0.1.26 内仍硬编码 6 + 3 = 9 款，
  下面 §3 把这个数组变成从 manifest 加载）
- 新增 `src/components/Picker.tsx`
- 新增 Tauri command:
  ```rust
  #[tauri::command]
  fn set_skin(skin: String) -> Result<(), String> {
      let id = SkinId::from_str(&skin);
      let mut cfg = Config::load();
      cfg.skin = id;
      cfg.save()?;
      emit_to_all("skin-changed", id);
      Ok(())
  }
  ```

### 路由二选一（实现细节）

**A. 多 HTML 入口（推荐）**：在 `vite.config.ts` 加 picker.html 作
为第二个 input，picker 窗口 url 设 `picker.html`。两个窗口完全独立，
不需要 React Router。

**B. 单 SPA + 路由参数**：`mouse.html?view=picker`，主 webview
+ picker 共用一个 bundle，根据 query 渲染不同组件。bundle 大一些
但开发更顺手。

→ **走 A**（两个窗口职责完全不同：mouse 是 always-on-top 透明角色，
picker 是普通 decorated 窗口，分开更清晰）。

## 3. Skin Manifest 抽象（数据驱动 · 为社区贡献铺路）

### 现状 vs 目标

- 现状：`skins.rs` 硬编码 enum + `skins.ts` 硬编码 SKINS 数组 + 调色板
  写死在 `PixelMouse.tsx` 里 → 每加一个新桌宠都要改 3 处
- 目标：定义 **manifest.json** 格式，**built-in skins 是用同一格式
  跟「以后的社区 skin」走同一加载管线** —— v0.1.26 不开放社区上传，
  但接口已经就位

### Manifest schema v1

```jsonc
// ~/.mouseclaw/skins/<id>/manifest.json
// (built-in skins 走 app resources 同样格式)
{
  "schema": "mouseclaw.skin/v1",
  "id": "cat-gray",
  "name": { "en": "Gray Cat", "zh": "小灰猫" },
  "species": "cat",          // mouse | cat | fox | frog | ...
  "author": { "name": "Edwin", "url": "https://github.com/edwin-hao-ai" },
  "license": "MIT",

  // 调色板：8 色锁定（参考 DESIGN.md）
  "palette": {
    "body":    "#cfcfcf",   // 主体
    "shadow":  "#8a8a8a",   // 暗部
    "accent":  "#ff9bb8",   // 耳朵/鼻子
    "eye":     "#1a1a1a",
    "highlight": "#ffffff",
    "extra1":  "#d63d6a",   // 物种特有（猫胡须、狐尾尖、蛙斑点）
    "extra2":  "",
    "extra3":  ""
  },

  // 体型变体 —— PixelMouse.tsx 已经支持的几种 + 新增
  "body_variant": "standard",  // standard | slim | chubby | robot | cat | fox | frog

  // 可选：物种特殊渲染指令（cat 加胡须；fox 加大尾巴；frog 改头型）
  "features": ["whiskers", "long_tail", "round_head"],

  "preview_state": "listen",  // picker 里默认显示哪个 state

  // 解锁条件（v0.1.26 全部 always；后面加等级时不改 schema）
  "unlock": { "type": "always" }
}
```

### 加载顺序

```
1. app bundle resources/skins/*/manifest.json   ← 内置 9 款
2. ~/.mouseclaw/skins/*/manifest.json           ← 未来用户安装
3. id 冲突时用户优先（用户可以"覆盖"官方皮肤）
```

### 后端 (`skins.rs`) 重构

把 enum 改成 **String id + 启动时加载的 registry**：

```rust
pub type SkinId = String;  // 不再是 enum

pub struct SkinRegistry {
    skins: HashMap<SkinId, SkinManifest>,
}

impl SkinRegistry {
    pub fn load() -> Self {
        let mut r = HashMap::new();
        // 1. built-in
        for entry in walk_bundle_resources("skins/") {
            if let Ok(m) = load_manifest(&entry) { r.insert(m.id.clone(), m); }
        }
        // 2. user-installed
        for entry in walk_user_dir("~/.mouseclaw/skins/") {
            if let Ok(m) = load_manifest(&entry) { r.insert(m.id.clone(), m); }
        }
        Self { skins: r }
    }

    pub fn get(&self, id: &str) -> Option<&SkinManifest> { self.skins.get(id) }
    pub fn all(&self) -> impl Iterator<Item = &SkinManifest> { self.skins.values() }
}
```

兼容性：现有 `skin: "classic" | "lab" | "field" | "ninja" | "cyber" | "golden"`
config 值不变 —— 这些 id 现在变成了 manifest id。

### 前端 (`PixelMouse.tsx`) 适配

`PixelMouse` 当前根据硬编码 `Skin` 对象渲染。改成：

1. 启动时 `invoke("list_skins")` 拿到所有 manifest
2. 用 manifest 里的 `palette` + `body_variant` + `features` 驱动渲染
3. Body variant 还是手写代码（mouse / cat / fox / frog 几个分支）
   —— 完全数据驱动 SVG 太复杂，先做半结构化

### 内置 skin 目录结构

```
src-tauri/resources/skins/
  classic/manifest.json
  lab/manifest.json
  field/manifest.json
  ninja/manifest.json
  cyber/manifest.json
  golden/manifest.json
  cat-gray/manifest.json    ← 新
  fox-red/manifest.json     ← 新
  frog-tree/manifest.json   ← 新
```

打进 `tauri.conf.json` `bundle.resources` 一并 ship。

## 4. 新增 3 个物种

| ID | 名 (ZH/EN) | 物种 | 特征 | 调色板要点 |
|---|---|---|---|---|
| `cat-gray` | 小灰猫 / Gray Cat | cat | 尖耳 · 胡须 · 长尾 | 灰 + 粉鼻 + 白胸毛 |
| `fox-red` | 赤狐 / Red Fox | fox | 大耳 · 蓬松尾 · 黑爪 | 橙红 + 白腹 + 黑爪尖 |
| `frog-tree` | 树蛙 / Tree Frog | frog | 圆头 · 突眼 · 蹼足 | 绿 + 白腹 + 红眼 |

每只在 6 个状态（sleep / listen / think / jump / write / block）下都画
SVG 像素艺术，按现有 16×16 网格 + 8 色调色板（参照
`docs/prototypes/mouse-skins-20260515.html`）。
