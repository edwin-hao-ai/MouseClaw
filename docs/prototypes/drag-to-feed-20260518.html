动画细节：跑步的关键是 cubic-bezier(0.2, 0.8, 0.3, 1) 让起步爆发、靠近时减速； 朝向用 --face: ±1 控制 scaleX；步态用 steps(2) 让像素抖动不糊。 长距离 > 800px 时在中段加一个 220ms 喘气帧避免传送感。

                                                                ┌── drop hit me ────┤
                                                                │                   │
                                                                ▼                   ▼

                                                                ▼            ▼

5 · 文档类型 + 处理策略

类型扩展名提取方式送给 Claude 的形式大小上限
图片 png · jpg · heic · webp · gif 直接读 bytes 复用截图 pipeline，作为 Read tool 的图片 attachment 10 MB
纯文本 txt · md · json · yaml · csv · log · 任意源码 std::fs::read_to_string prompt 内联 [文档 README.md]\n...\n[/文档] 200 KB (~50K token)
PDF pdf 系统自带 mdimport / pdftotext，无依赖打包 抽文本后内联，>3 页时分段 + 页号标注 20 MB / 100 页
DOCX docx unzip → 取 word/document.xml 抽 <w:t> 文本 同纯文本 10 MB
XLSX xlsx unzip → 取 xl/sharedStrings.xml + 各 sheet 转 Markdown 表格内联 5 MB
拒绝 app · exe · dmg · zip · 视频 · 音频 · >上限 不处理 桌宠摇头吐出 + 气泡 "❌ 这个吃不下" —
多文件喂：用户拖多个文件 → 桌宠"咬一摞"动画 → 都吃下，prompt 里依次拼接 [文档 1] ... [文档 2]。 上限 5 个 / 总大小 30 MB；超了只吃前 N 个 + 警告气泡。

6 · 工程实现

6.1 拖动检测：把桌宠窗口变成全屏 drop overlay

桌宠平时是 64×64 透明小窗。OS 检测到拖动开始那一刻（macOS：NSPasteboard 监听 + window draggingEntered:）， Tauri 后端立刻把窗口扩成全屏 1px-transparent overlay（pointer-events: none，除了桌宠 hitbox）， 这样任何屏幕位置的拖动都能被 webview 的 dragenter/dragover/drop 事件捕获。drop 完成或拖动取消 → 收回 64×64。

  • Tauri 2 原生事件：tauri://drag-enter / tauri://drag-over / tauri://drag-drop / tauri://drag-leave
  • 需要在 tauri.conf.json 打开 dragDropEnabled: true（默认就开）
  • 放大窗口的瞬间不能抢焦点（保持 NSPanel + nonactivating），否则前台 app 失焦体验劣化
  • 拖动期间老鼠用 cursor_position 跟随鼠标位置（V1 唯一允许跟随鼠标的场景）

6.2 文件路径拿到之后

// src-tauri/src/feed.rs
pub async fn ingest(paths: Vec<PathBuf>) -> Result<FeedBundle> {
    let mut bundle = FeedBundle::new();
    for path in paths.iter().take(MAX_FILES) {
        let kind = classify(&path)?;  // 看扩展名 + magic bytes
        match kind {
            Kind::Image  => bundle.add_image(path)?,
            Kind::Text   => bundle.add_text(path, fs::read_to_string(path)?)?,
            Kind::Pdf    => bundle.add_text(path, pdf_to_text(path)?)?,   // mdimport
            Kind::Docx   => bundle.add_text(path, docx_to_text(path)?)?,
            Kind::Xlsx   => bundle.add_text(path, xlsx_to_md(path)?)?,
            Kind::Reject => bundle.reject(path, "格式不支持"),
        }
    }
    Ok(bundle)
}

6.3 自动激活语音 IME

吞咽动画结束的 onAnimationEnd 里 invoke("voice_ime_start", { context: bundle.id })。 录音 → sherpa-onnx 转写 → 拼成最终 prompt：
[已附文档]\n- README.md (14KB markdown)\n- screenshot.png (image)\n\n[/已附文档]\n\n{user_voice_transcript}

7 · 风险 + 边界

风险影响缓解
全屏 overlay 偷焦点 用户 Finder 拖文件时桌宠把 Finder 拍到后台 → drag session 中断 macOS 用 NSPanel + nonactivating style mask；overlay 期间 orderFront: 不抢 key
不是拖文件的拖动也触发 用户拖文字选区 / 拖窗口标题栏 / Mission Control 触发 sniff 只在 dragenter 看到 dataTransfer.types.includes('Files') 时才进入 sniff
大文件读卡住 用户拖一个 500MB PDF，UI 冻 30 秒 spawn 单独 tokio task；超 200ms 没回 → 气泡显示 "嚼一下…" 进度；超 5s 失败 → 吐出来
语音 IME 没人说话 吃完了但用户没问，桌宠一直录 3 秒静默自动结束录音，发"我吃完了，没问题就走了 🍽️→💤" 气泡，回 idle
用户拖到桌宠脸上又拖走 桌宠张嘴等待但 drop 取消，需要回 idle 监听 tauri://drag-leave + 全局 dragend，2s 没有 drop → 失望气泡 "🥲 不给吃？" → 跑回原位
跨 app 拖动数据不全 从浏览器拖图片可能是 URL 不是文件 识别 text/uri-list：本地 file:// 走文件流程；http(s):// 先 download 到 /tmp/mouseclaw-feed-XXX 再处理
终端窗口在前台 用户在终端 drag-and-drop 路径补全，触发桌宠 检测前台 app bundle id 是 Terminal / iTerm / Warp → overlay 期间不抢响应，drop 让终端先处理
开发节奏建议：
  • P0（1 天）：图片 + 纯文本 + md，全屏 overlay + 跑步动画 + 吞咽 + 自动语音
  • P1（半天）：PDF / DOCX / XLSX 提取（外挂 macOS mdimport，零新依赖）
  • P2（半天）：多文件、URL 拖入、终端豁免、3s 静默回 idle
  • 共 ~2 天，不超 v0.4 预算
