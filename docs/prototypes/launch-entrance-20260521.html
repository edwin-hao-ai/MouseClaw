启动场景检测方式档位行为
首次安装 / Onboarding 完成 config 无 seen_entrance 标记 炸（loud） 左边探头 → 横冲到中央 → 急刹 → 张望+蹦跶+甩尾「在这呢」→ 跑去右下角坐下 → 回头瞥一眼。~2.8s

⑤ 设计决策 / 边界（动手写 Rust 前必须答完的 UX 10 问）

  • 可发现性：入场动画本身就是「MouseClaw 活着、在这」的告知。炸档让首次用户秒懂有这只老鼠。
  • 可打断（硬规则）：入场任意阶段，用户点击 / 按键 / 触发任务 → 立刻 snap 到 anchor + idle，绝不逼用户看完过场。 实现上整段动画是一个可取消的 task，收到任何前台输入事件就 abort。
  • 不抢焦点：overlay 窗口 focus:false，入场不夺走键盘焦点；用户该敲字敲字。
  • 实现关键 = 让窗口本体跑，不是开个全屏透明窗：入场 = 那个 80×80 的 pet 窗口 从屏幕边缘 滑动它的物理位置 到 anchor（Tauri set window position 逐帧）。 绝不把 overlay 撑成全屏来"装下"路径——那会重演 f253762 的 WebKit backing 遮挡问题 （桌面图标不可点 / Mission Control 行为怪）。这点和 pet-runs-to-greet 的窗口移动方案一致。
  • 全皮肤适配：run/skid/hop/张望都作用在整只 SVG（对 9 个 body variant 都成立）； 表情拍由 .mc-ear / .mc-tail 子组承担——蛙走 .mc-ear-frog 鼓气 keyframe， 狐尾走 .mc-tail-wag-big 大摆幅。颜色全部来自 skins.ts palette，零 hardcode。
  • 多屏：在光标所在那一屏入场并停到那屏的 anchor，不跨屏横冲。
  • 前台是全屏 app / 演示模式：always-on-top 在 fullscreen space 被系统隐藏 → 入场静默跳过，下次普通桌面再演（炸档标记还没消耗就保留）。
  • prefers-reduced-motion：三档全部降级为「直接出现在 anchor」，无横冲无蹦跶（见本页 media query；真机同样处理）。
  • 长期使用不烦：炸档一生一次、轻档每天但 <1s 且不挡视线——这是「第一印象惊艳」和「每天不打扰」的平衡点。
