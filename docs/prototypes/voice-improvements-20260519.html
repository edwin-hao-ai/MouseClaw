语音输入三个基础改进

v0.4 候选 · 2026-05-19 · 全部本地 · 不引入大模型 · 不增加常驻内存

目标：让"按住快捷键说一句话"的体验明显超过 Typeless。三件事都基于 现有 sherpa-onnx 栈，不引入本地 LLM，不增加常驻内存（< 600MB 上限不动）。 预算合计：≤ 1 周。

P1 · 术语库（hotwords）—— Typeless 没有的差异化

sherpa-onnx 原生支持 hotwords_file + hotwords_score， 在解码时把指定词的概率拉高。零额外模型 · 零延迟 · 零成本。 程序员说「Tauri」「useEffect」「async/await」从此再也不会被听成「他爱瑞」「use effect」。

命中可视化（关键 UX 决定）

识别出术语库命中词时，气泡里那个词短暂高亮 0.5 秒，让用户感知"啊它真的认识这个词"。 没有这个反馈用户不知道功能有没有 work。

P2 · 3 秒规则纠错（不用 LLM）

刚听写完 3 秒内，再次按快捷键说一句"修正口令"，自动改掉刚写入的文本。 覆盖 4 个高频 pattern，纯正则 + 字符串匹配，< 5ms 完成，零成本。

支持的 4 个 pattern

说法动作例子
「把 X 改成 Y」
「X 改成 Y」		 把刚写入文本里最后一处 X 替换成 Y 「把张三改成李四」
「不是 X，是 Y」
「不对，是 Y」		 替换最近一个名词短语（启发式：最后一个名字 / 数字 / 标识符） 「不对，是 42」
「删掉 X 」
「去掉 X 」		 移除刚写入文本里最后一处 X（连同前导空格） 「删掉那个 the」
「重说」
「全部删掉」		 整段撤销 · 等同 ⌘Z（发模拟键盘事件） 「重说」

触发窗口 · 视觉反馈（关键 UX 决定）

听写完气泡变成「✓ 已写入」绿色 success 状态，头顶亮一道 3 秒倒数细线 提示"在这 3 秒里你还可以说改正"。3 秒后线消失，气泡淡出，恢复 sleep。

刚写完 · 可纠错窗口3 秒

⚠️ 同一次 sherpa session continue 不重置窗口——3 秒是从"上次写入完成"起算。 按快捷键开新录音 → 立刻判定为「可能是纠错」分支。

失败兜底 · 不要骚扰用户

  • 没匹配到任何 pattern → 当成普通新写入处理（追加到光标，不改前文）
  • 匹配到 pattern 但 X 在前文里找不到 → 气泡 amber：没找到「张三」，按 Esc 关闭
  • 「重说」之后又说了普通话 → 撤销 + 写入新内容，两步动作合并为一次"听起来很顺"的体验
  • 前台 app 是终端 → 直接禁用纠错（不能模拟键盘改前文，可能误执行命令）—— 与 Mode B 同源风险

取舍 & 顺序

档预算新模型内存增量用户感知Typeless 比较
P0 · 混说默认0.5 天无0 立刻：「再也不用切语言了」 持平（它也有，但我们隐私+本地胜出）
P1 · 术语库2-3 天无（用 sherpa hotwords）~5 KB（词表内存常驻） 程序员瞬间种草 独家 它没有
P2 · 规则纠错3-5 天无0 "它居然能听懂我改话"——惊艳点 它有 LLM 版纠错；我们规则版覆盖 70% 案例，剩下 30% 留空（不假装）
合计 0~5 KB ≤ 1 周 · 不引入 LLM · DMG 不变胖 · 常驻内存不变

建议执行顺序

  1. D1 · P0 落地 + commit（半天）—— 一步出货，发 v0.4.0-rc1 给少量用户试
  2. D2-D4 · P1 落地—— 词表 + UI + 内置程序员词表，发 v0.4.0-rc2
  3. D5-D7 · P2 落地—— 规则纠错 + 3 秒窗口 UX，发 v0.4.0 正式版
  4. 正式版 release notes 主打「程序员的语音输入」角度，对标 Typeless

未做的事（坦白 · CLAUDE.md 头号规则）

  • ❌ 语气切换（邮件 vs IM 不同正式度）—— 需要 LLM，本轮跳过
  • ❌ 写作风格学习（"像你"）—— 需要 LLM + 数据沉淀，本轮跳过
  • ❌ 30% 模糊纠错案例（"那个数字"指哪个）—— 规则覆盖不了，本轮跳过
  • ❌ Windows 支持 —— 仍是 V2 议题

这些都不是"做不到"，是明确不在本轮范围。等用户跑起来 70% 覆盖之后再决定要不要追剩下的 30%。
