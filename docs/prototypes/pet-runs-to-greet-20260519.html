② 关键交互细节

阶段视觉关键时序
0. 空闲 桌宠在 anchor（如右下角），breathe 动画，眼半闭 窗口 80×80，不挡任何东西
1. 抓起文件 用户在 Finder 按下文件，开始拖。系统 ghost preview 跟着光标 MouseClaw 还不知道 drag 发生了 —— 直到 NSDragging 进我们某个窗口
2. 系统级 drag enter ⚡ 用户光标进入屏幕任意位置后，我们的隐形 drag-detector 全屏窗口收到 draggingEntered: 事件转发给 feed_flow。pet 立即 ear-perk + 切到 running 状态
3. 跑步迎接 pet 从 anchor 位置 lerp 到光标附近，~400ms ease-out，跑步精灵 到达后切 waiting 状态，张嘴 + ring-pulse 提示"放这"
4. 跟随光标 cursor_follow 30fps 让 pet 紧贴光标侧下方（约 32px offset） 用户拖到哪 pet 跟到哪，距离始终 ≤ 32px
5. 放手 = 吃 drop → pet eating 动画 4 帧 chomp，bubble「🍽 收到 N 个文件」 file 内容走现有 feed pipeline，AI 召唤进 voice-confirm 倒数
X. 取消 = 滑回 用户拖出屏幕 / Esc / 拖回 Finder：pet 200ms debounce 后滑回 anchor 不立刻退场避免抖动（用户瞬间 leave/enter 切换很常见）

❌ 方案 X：把 mouse overlay 扩到全屏
简单粗暴：让 80×80 → 全屏。drag enter 全屏覆盖。

致命问题：f253762 用户实测「即使 transparent + ignore_cursor_events， WebKit 在大窗口上仍渲染半透明 backing，Mission Control / Stage Manager 行为奇怪，桌面图标不可点。这是为啥从 320×320 缩到 80×80 的根本原因。」

不可重蹈覆辙。
✅ 方案 A：独立纯 NSWindow drag-detector
新建一个**不挂 webview** 的纯原生 NSWindow，全屏 transparent + always-on-top + setIgnoresMouseEvents:YES。

关键技术点：
  1. 通过 registerForDraggedTypes: 注册接收 file URL 类型
  2. 没有 WebKit backing → 不产生 f253762 描述的视觉遮挡
  3. setIgnoresMouseEvents 阻止点击但 不阻止 NSDragging （macOS 这俩走不同 event path · 已查证）
  4. draggingEntered/Updated/Exited/performDrag 回调通过 NSObject subclass 实现，FFI 到 Rust 转发给 feed_flow

预算：~200 行 obj-c FFI，一天能 ship。

④ 失败模式 / 边界

  • 多屏：drag-detector 窗口 cover 主屏 + 副屏（macOS NSScreen.screens 遍历）。pet 跑向**光标所在那一屏**的 anchor，不跨屏
  • 非文件 drag（如 Finder 内部排序、文本选区拖动）：注册的 dragged types 只包含 NSPasteboardTypeFileURL，文本 drag 不会触发 pet
  • Mission Control 激活时：always-on-top 窗口在 Mission Control 里被系统压到下面（macOS 行为），drag-detector 跟桌宠一起暂时不响应——可接受
  • 全屏 app（Keynote 演示模式）：always-on-top 在 fullscreen space 里被隐藏。drag-detector 暂时失效——可接受（演示时不会拖文件）
  • 非常快速 drag（500ms 内 pickup→drop）：pet 还没跑到光标用户已经 drop 了。drop 走 fallback：直接定位 pet 到 drop 点，立刻 eating 动画。不要让用户觉得"丢了"
  • 用户已经在 anchor 上方拖：pet 不用跑（距离 < 100px 时省略动画，直接进 waiting）
  • 窗口尺寸切换：detector 全屏始终；pet overlay 仍走 f253762 的 80↔320 切换。两个窗口独立

⑤ 实现路径（拍板后）

  1. D1 · obj-c FFI 骨架：新文件 src-tauri/src/drag_detector.rs。 创建透明 NSWindow + NSView subclass MCDragView 重写 draggingEntered/Updated/Exited/performDragOperation。 ~150 LOC
  2. D1 · 事件转发：4 个回调通过 extern "C" fn 桥到 Rust。 Rust 端拿到 cursor screen pos + file paths → 调 feed_flow::on_drag_enter / on_drag_leave。 ~50 LOC
  3. D2 · 多屏 + always-on-top + level：用 NSStatusWindowLevel 让窗口浮在最上， 覆盖所有 NSScreen。setCollectionBehavior: 设 ignoresCycle + stationary。 ~30 LOC
  4. D2 · 老的 mouse overlay 的 drag-drop handler 删掉：现在统一从 drag-detector 走， 避免双倍触发。lib.rs 里的 DragDrop event handler 改成只接 detector forward 的消息
